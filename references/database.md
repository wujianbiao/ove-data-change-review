# 数据库、查询频率与规模

只检查本次相关路径；发现按主 Skill 分级。引擎、版本、数据源及执行器从仓库核实，不假定某个 ORM、部署平台或默认分支。

## 查询正确性与成本

- 追到真实 SQL/参数，含 ORM 生成语句。列正常及合理最坏的租户、实体、时间窗、数据量/倾斜、返回上限、QPS、并发、重试与回源。
- 核对行的业务含义、统计粒度、去重键、单位/精度、null/缺失、迟到/重复及基线。参数化值，动态标识符白名单；空值不能自动当零。
- 识别联接后聚合、多层分组、窗口函数、相关子查询、数组展开、无界聚合结果、N+1、大 OFFSET、排序/哈希溢出、锁等待和连接占用；应用内 groupBy/reduce/sort 同样计成本。
- 给过滤、展开、联接、分组各阶段的行数、数组上界、组数和结果尺寸。独立数组同时展开可由 N 放大到 N×L1×L2；COUNT/SUM可能重复计数，嵌套条件要核对是否命中同一元素。
- 高频/大表/新聚合用代表性计划及前后负载证据，注明参数、规模、冷热缓存、并发、时延计时边界、扫描/loops、内存和临时I/O。计划cost不是毫秒，LIMIT不约束此前扫描/聚合。
- 当前及发布/保留可预见峰值超预算或缺关键证据即强阻塞。低风险有界查询可引用核对仍有效的基线；未来才发生的风险按规模计划登记。

## 规模放大与字段设计

- 说明当前行数/表与索引字节、日增、保留峰值、热点及分布。千万行是重点核查信号；宽行、高频或大扇出也可能在更小规模出问题。
- 说明本次字段类型/范围/精度、实际平均和高分位长度、空值、重复载荷及键/INCLUDE用途。varchar上限不等于固定每行占用；不能为省空间破坏ID范围或旧数据精度。
- 行数×逻辑字节差仅作起点；逐个核对包含字段的索引条目数，再考虑页/对齐、压缩/TOAST、索引去重、WAL、临时构建空间和副本。PG普通二级索引不会自动复制整个主键。
- 当前类型/键/成本边界必须确定；健康小表的细微布局改进可建议，已知远期风险须有阈值/指标/负责人/足够提前量，不能靠“以后优化”掩盖近期越界。

## 索引与字段顺序

- 先对比仓库迁移及授权可用的实际索引目录：键顺序、方向、表达式、谓词、方法/operator class、INCLUDE、唯一性和约束归属。IF NOT EXISTS按名称检查，不按语义去重。
- 每个增删改索引说明受益 SQL/频次、既有索引为何不能满足、尺寸/写入/WAL、锁/事务、构建空间及失败恢复；约束用途与查询加速分别论证。
- B-tree结合常用等值前缀、首个范围、ORDER BY方向及稳定游标安排键序；区分度看租户内基数、null、倾斜与相关性。不机械“最高区分度放第一”，也不一律否定低区分度键。
- 核对可选中间列缺失和不同调用组合。PG18可能采用skip scan，不能宣称缺前缀必然失效；以实际版本、分布和计划为准。
- INCLUDE增加条目但不充当搜索键；覆盖列齐全也不保证免回表。不能为覆盖查询塞入无必要的宽字段。
- 前缀重合或idx_scan=0不足以证明可删；核对统计窗口、低频任务与约束。并发建索引等方式要匹配真实runner，不机械添加关键字。

## 个人默认：JSONB仅存取

允许原始/稀疏扩展内容随记录存取，核对结构与尺寸。禁止JSONB及路径提取、cast、函数/展开值用于WHERE、JOIN ON、HAVING等条件，含ORM、视图、CTE或应用过滤的间接依赖；禁止新增涉及JSONB的键、提取表达式、部分谓词或INCLUDE索引。

需要检索、分组或排序的稳定字段独立类型化或关系投影，并验证写入一致性、回填和兼容。性能好、表小或已有GIN不豁免默认策略。用户或目标仓库明确采用其他策略时记录依据；不要把PG支持JSONB索引误写成“必然索引失效”。其他引擎的JSON查询按各自规则审查。

## 查询频率与业务时效

- 先说明变化频率、允许陈旧时间及触发方式。低频配置优先打开、保存、手动或变更通知；库存、当前任务、指令状态按真实时效另定，不能一律手动或套固定秒数。
- 稳态请求/小时≈Σ(活跃窗口或设备数×每轮请求数×3600÷间隔秒)，另计首次、焦点/重连/推送与重试。数据库负载还包含鉴权、权限、业务SQL及回源；HTTP次数不等于SQL次数。
- 核对空闲、隐藏/关闭、卸载、切租户后的行为，以及重叠请求、重复订阅、合并去重、退避和恢复补读。保存及时反馈，旧响应不能覆盖新保存或新身份。
- 持续轮询尤其秒级要有必要性和总负载依据。单次快、缓存命中、只交降频公式不能单独放行；优化也不能破坏已承诺时效。

## 写路径与并发

- 唯一约束、ON CONFLICT、版本CAS、单调守卫、原子计数是数据库兜底；先查再插不等于并发安全。批写/回填验证部分成功、重复、乱序、重启及限速/断点。
- 个人默认：业务策略保持可读、可测试。多写目标CTE链、INSERT…SELECT…WHERE NOT EXISTS条件写、SET中CASE业务分支须说明归属；无充分原子热点理由时改为显式事务和业务代码，联接超过3表补逐表作用/扇出说明。
- 拆分时按真实竞态选择行锁、隔离级别或条件写/CAS；读→判定→写仍在同一正确事务/版本边界内，审计与业务写同成同败。禁止把原子语句拆成无保护往返；真实热点例外须有必要性、竞态测试和适用人工确认。
- 核对租户路由、冲突键、局部upsert、锁顺序、连接归还、取消排空与首错保留。更新索引字段、宽载荷或频率时重新计算写放大。
