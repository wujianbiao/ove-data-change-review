# 报告与确认

只写适用事实，未变项引用核对仍有效的基线；缺证据与已证实缺陷分开。

## 无影响

```text
结论：无数据影响。
范围：各类介质均无变化的diff/调用路径依据；DDL无及核查范围。
版本：仓库、源/目标ref与SHA、merge-base、检查时间、未提交状态。
```

## 有影响或待核实

| 项          | 事实                                                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------------------------------------- |
| 版本/范围   | 上述审查版本；实际入口→操作→读/重放方，对象、身份、权威来源/副本、数据版本与DDL有/无/待核实                               |
| 规模/索引   | 当前及发布/保留峰值、分布/倾斜、字段范围/实际宽度、相关索引条目成本、真实谓词/区分度/键序/排序及预算                      |
| 查询/频率   | SQL/ORM/应用计算，展开与聚合正确性；变化频率、允许陈旧时间、触发与轮询必要性；窗口/设备、鉴权/业务/回源总量               |
| 慢查询风险  | 当前与可预见峰值下可接受/不可接受/待验证及参数、计划、成本和时延依据；只把该范围后两者列为强阻塞                          |
| 正确性/兼容 | 租户、幂等/并发、失败/重放、TTL/清理、升级矩阵、旧端上传/回执、发布/回退和生产执行状态                                    |
| 分级        | 每项低/中/高影响及强阻塞/建议优化/规模触发；阻塞解除条件，建议收益/代价，未来风险的安全依据、指标/阈值/负责人/提前量/验收 |
| 证据        | 命令及结果、样本/规模/并发、计时边界；估算/合成/生产分列，未运行项目与原因                                                |
| 确认        | 负责研发及适用独立评审的身份、时间、原始记录、对象/成本/兼容/发布恢复范围，绑定源/目标/报告/数据版本                      |

通过只表示无未解除强阻塞且必要确认齐全，不要求建议或尚未触发的治理全部完成。需要人工确认时先记待确认，不能用Agent或自勾选代签。

发布/配置/不兼容变化明确列出。详细报告可作为仓库文档或附件，版本绑定放在PR/MR描述中，避免报告包含自己的提交SHA形成循环；工具不能回读远端状态时如实说明。
