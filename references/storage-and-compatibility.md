# 存储、生命周期与混合版本

## 各介质必查

| 对象                 | 要核实的事实                                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------- |
| 通用数据             | 租户/账号身份、权威来源和副本、读写/重放方、幂等键、删除后旧任务写回、部分成功后的补偿/对账           |
| 内存/共享缓存        | key与值版本、隔离、TTL/续期、失效与回填顺序、旧值覆盖、多进程副本、容量/淘汰、冷启动或批量失效回源    |
| 文件/对象/客户端存储 | 路径/归属、半写/磁盘满、缺对象、内容与元数据一致性、hash、同路径覆盖和老客户端读法                    |
| 消息/同步            | 提交→发送→ack边界、重复/乱序/重放、离线积压、回执丢失、失败项与成功项区分；HTTP成功不等于业务已持久化 |
| 格式/revision        | 缺失/未知/损坏版本的处理、revision实际比较、升级标记和内容原子提交、旧写入方是否覆盖新字段            |

不要把唯一待同步数据、去重状态或锁当作可删缓存。声称可重建须证明来源完整、身份/结果正确和回源预算；TTL或重启本身不证明正确性。

容量核对日增对象/行/字节、历史副本、积压和保留期；清理有负责人、周期、批次、重入与失败检测。DELETE不保证立即归还磁盘；核对长事务、vacuum、复制与回填峰值。

## DDL与协议

- 每次给DDL有/无/待核实；有则列迁移文件或生成规则、库/schema/对象、旧→新定义、执行入口/顺序、锁/事务/超时、生产是否执行及回退边界。
- 遵循目标仓库的迁移目录和runner；已执行迁移保持不可变，不把请求期DDL或新schema快照当作迁移替代。启动是fail-open还是fail-fast必须读代码核实，不预设部署顺序。
- 代码SHA、数据库版本、序列化格式、缓存命名空间和协议版本分开记录；没有version字段也可能改变语义。

| 组合                       | 必须验证的业务结果                                                    |
| -------------------------- | --------------------------------------------------------------------- |
| 旧客户端＋新服务           | 旧请求通过适用校验、正确入库，旧端能处理响应/逐项回执，离线积压可恢复 |
| 新客户端＋旧服务或服务回退 | 能力判断、降级或准入有效，不向不兼容服务持续发送新请求                |
| 新读写方＋旧数据           | 缺字段、旧单位/格式和未知枚举不被误读，不将解析失败变为空值写回       |
| 旧读写方＋新数据           | 不误读、不清新字段、不覆盖为旧格式；不支持时有已验证的限制与数据保全  |

不要求所有组合无条件兼容，但实际发布/回退中会出现的组合必须支持或被可信准入阻止；范围未知或必需组合缺证据属强阻塞。用真实旧版本样例/解析器，不用当前helper伪装旧端。

请求/响应核对字段、单位、null/默认、枚举、分页、鉴权/签名和错误语义。上传覆盖部分成功、重复、拒绝、超时与旧端重试；不得误标已同步或删除唯一待传项。

## 发布和恢复

按依赖决定：兼容扩展→兼容读写方→可重入回填并对账→切读/灰度→观察后收缩。校验并发写、半迁移、重复执行、失败重启和仅回退代码后的数据。

删列、改类型、收紧约束、缓存key/格式切换等按实际兼容窗口分阶段；同次发布连续扩展和删旧不算安全过渡。分别报告结构、数据、缓存、协议和代码是否已执行/上线。
